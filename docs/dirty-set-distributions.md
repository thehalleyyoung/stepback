# Empirical dirty-set distributions

> **Step 66 — 100_STEPS.md**: publish empirical dirty-set distributions over
> synthetic fixtures, public benchmark corpora, and anonymized production traces.

This document reports empirical distributions of the fraction of steps marked
dirty by `compute_dirty_set` under a single typed substitution, across four
representative trace corpora and three substitution-position strategies.

The full machine-readable results live in
`bench-results/dirty-set-distributions.json` (generated with
`stepback bench dirty-set-distributions --n-trials 20 --n-steps 50 --seed 0`).

---

## Methodology

### Metric

For each trial we record the **dirty fraction** `f = dirty_count / step_count`
where `dirty_count` is the number of steps in the dirty set D returned by
`compute_dirty_set` under a single substitution.  `f = 0` means a complete
cache hit (no substitution is needed); `f = 1` means every step must be
re-executed.  A useful replay saves `1 - f` of the LLM/tool calls.

### Corpora

| Corpus | Description | Fixed length? |
|---|---|---|
| `linear_chain` | Purely sequential `llm_call` / `tool_call` chain. Worst case for dirty propagation: every step has a `context_from_parent` edge, so a substitution at step *k* makes the entire suffix dirty. | `--n-steps` (default 50) |
| `parallel_wide` | Single fan-out / fan-in block with *W* branches, *W* ∈ {3..10} chosen uniformly per trial. Substituting inside one branch keeps siblings clean (B1–B3 isolation). | 1 + 2W + 1 steps |
| `mixed_synthetic` | Mix of sequential steps and occasional parallel blocks, generated by `SyntheticTrace` (the reference bench builder). | `--n-steps` |
| `agent_fixture` | The canonical 12-step customer-payments agent from `stepback.testing.run_recorded_agent`. Fixed topology; represents a realistic recorded LLM + tool trace. | 12 steps |

### Substitution strategies

Each corpus × strategy cell is run with `n_trials = 20` independent traces.

| Position | Description |
|---|---|
| `random` | Substitution at a uniformly random `llm_call` or `tool_call` step. |
| `early` | Substitution in the first 25 % of substitutable steps (large suffix → large dirty set). |
| `late` | Substitution in the last 25 % of substitutable steps (short suffix → small dirty set). |

Two substitution types are used: `PromptSubstitution` (targets `llm_call`
steps) and `ToolOutputSubstitution` (targets `tool_call` steps).  If no
matching step exists for the requested type the other type is used.

## Results

### `linear_chain` (n=50 steps, 20 trials each)

| position | sub_kind | p50 | p95 | mean |
|---|---|--:|--:|--:|
| random | PromptSubstitution | 0.480 | 1.000 | 0.480 |
| random | ToolOutputSubstitution | 0.440 | 0.980 | 0.497 |
| early | PromptSubstitution | 0.880 | 1.000 | 0.897 |
| early | ToolOutputSubstitution | 0.860 | 0.980 | 0.852 |
| late | PromptSubstitution | 0.140 | 0.320 | 0.127 |
| late | ToolOutputSubstitution | 0.180 | 0.380 | 0.177 |

**Interpretation.** On a purely linear chain, dirty-set growth is proportional
to suffix length.  A random substitution dirtied ~48 % of steps at median; an
early substitution dirtied ~88 %; a late substitution only ~14–18 %.  The
cost reduction factor for random substitutions is ~2×.

### `parallel_wide` (W branches, W ∈ {3..10}, 20 trials each)

| position | sub_kind | p50 | p95 | mean |
|---|---|--:|--:|--:|
| random | PromptSubstitution | 0.222 | 1.000 | 0.308 |
| random | ToolOutputSubstitution | 0.167 | 0.300 | 0.184 |
| early | PromptSubstitution | 1.000 | 1.000 | 0.759 |
| early | ToolOutputSubstitution | 0.167 | 0.300 | 0.181 |
| late | PromptSubstitution | 0.167 | 0.286 | 0.154 |
| late | ToolOutputSubstitution | 0.214 | 0.300 | 0.207 |

**Interpretation.** For `ToolOutputSubstitution` inside a branch, dirty
fractions are low (median ~17 %) regardless of position because sibling
branches stay clean (B1–B3 isolation).  `PromptSubstitution` at an early
position occasionally hits the pre-branch dispatch step, which then dirtying
all branches (the high p50=1.0 for `early / Prompt`).

### `mixed_synthetic` (n=50 steps, 20 trials each)

| position | sub_kind | p50 | p95 | mean |
|---|---|--:|--:|--:|
| random | PromptSubstitution | 0.420 | 1.000 | 0.482 |
| random | ToolOutputSubstitution | 0.480 | 0.960 | 0.458 |
| early | PromptSubstitution | 0.880 | 1.000 | 0.911 |
| early | ToolOutputSubstitution | 0.820 | 0.940 | 0.809 |
| late | PromptSubstitution | 0.100 | 0.220 | 0.115 |
| late | ToolOutputSubstitution | 0.080 | 0.320 | 0.120 |

**Interpretation.** Very similar to `linear_chain`; the occasional parallel
blocks do not dramatically change the dirty fraction because each step has a
`context_from_parent` edge.  Late substitutions achieve ~10× cost reduction
(median dirty fraction ~10 %).

### `agent_fixture` (12 steps, fixed topology, 20 trials each)

| position | sub_kind | p50 | p95 | mean |
|---|---|--:|--:|--:|
| random | PromptSubstitution | 0.667 | 1.000 | 0.650 |
| random | ToolOutputSubstitution | 0.583 | 0.917 | 0.483 |
| early | PromptSubstitution | 1.000 | 1.000 | 1.000 |
| early | ToolOutputSubstitution | 0.917 | 0.917 | 0.917 |
| late | PromptSubstitution | 0.333 | 0.333 | 0.258 |
| late | ToolOutputSubstitution | 0.250 | 0.250 | 0.183 |

**Interpretation.** The 12-step customer-payments agent is a mostly-linear
pipeline (LLM decides → tool lookup → LLM finalises → tool executes).  A
`ToolOutputSubstitution` targeting the `lookup_customer` step at a late
position dirtied only ~25 % of steps (median), consistent with the B2/B3
property that only downstream dependent steps become dirty.

## Relationship to the README headline and Step 67 reconciliation

The current README makes **no specific numeric claim** about dirty-set
size; it states only the asymptotic bound O(dirty\_set) vs. O(N).  An
earlier version cited a ">60× cost reduction on a representative 200-step
trace with median dirty-set of 3" — those numbers were anchored to the
11-step parallel-branch fixture (`stepback.testing.run_parallel_agent`),
where substituting one branch leaves two sibling branches clean and dirties
only 3 steps (branch + join + downstream synthesise), giving the small
dirty-set size.

The results above do not reproduce a >60× reduction because:

1. The synthetic corpora use `context_from_parent` edges (worst-case for
   dirty growth), giving 2–10× under random substitutions.
2. The 12-step linear fixture gives a conservative static dirty count of
   11/12 under an early substitution — the O(N − k) worst case for linear
   chains.  See `docs/dirty-set.md §9` for the full reconciliation (Step 67):
   the runtime replay engine with stale-cache detection (Step 61) may show
   fewer dirty steps when re-executed outputs match recorded outputs.

Small dirty sets arise from **parallel branches** (B1–B3 sibling isolation)
or **late substitutions** (short downstream suffix).  See `bench-results/README.md`
for the synthetic calibration data and the step-67 reconciliation summary.

## How to regenerate

```sh
stepback bench dirty-set-distributions \
    --n-trials 20 \
    --n-steps 50 \
    --seed 0 \
    --out bench-results/dirty-set-distributions.json
```

All inputs are deterministic (RNG seeded from `--seed 0`) so re-runs on
the same codebase produce the same distributions; only wall-clock times vary.

To run a quick smoke check with fewer trials:

```sh
stepback bench dirty-set-distributions \
    --n-trials 5 --n-steps 20 \
    --corpora linear_chain,parallel_wide
```

## Future work

* **Public benchmark corpora.** Once public LLM-trace datasets are available
  (e.g., OpenAI Evals traces, MLCommons inference logs) the same
  `CorpusDistribution` / `DistributionSuite` pipeline can be applied to
  them.  A loader hook in `dirty_set_distributions.py` is the intended
  extension point.
* **Anonymized production traces.** Organizations running `stepback` in
  production can use `stepback.analytics.record_from_summary` to emit
  `DirtySetRecord` rows to ClickHouse (see step 65) and then query the
  distribution from the warehouse without needing to ship raw traces.
* **Dirty-equality short-circuit.** An extension to the propagation
  algorithm that re-executes a dirty step and short-circuits the dirty
  chain if the output hash happens to match the recorded value (see
  `divergence.py` §"Divergence-detection severity levels") would shrink the
  empirical dirty fractions significantly for non-deterministic-but-stable
  models.
